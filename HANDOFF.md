# HomeInventory Handoff

## Product Goal

Build a local-first iPhone inventory app that turns home walkthroughs, photo sweeps, and eventually a live camera stream into an assistant-ready catalog of individual belongings. The assistant should later use this data for cooking, restocking, organizing, and finding where things are.

The key user expectation is object-level inventory entries, not broad image categories. Each saved item should have a crop/photo, name, category, room/area/container, confidence, condition when possible, OCR/barcode metadata, and a flag for detail scans or laptop review when the phone cannot resolve it.

## Current State (2026-08-26)

Architecture is now **detect-then-classify**: cheap localizers find objects, MobileCLIP names them.

- Native SwiftUI iOS app in `Inventory/`, generated by XcodeGen from `project.yml`.
- **Localizers** (in order): live-scan seeded YOLO boxes → static `yolo26n` YOLO pass → `VNGenerateForegroundInstanceMaskRequest` subject lifting → objectness saliency → whole-frame fallback. YOLO class labels are treated as weak evidence only.
- **Identification** is zero-shot MobileCLIP-S2 (Core ML, on-device) against a runtime-editable vocabulary: `Inventory/Resources/household-vocabulary.json` (~320 items with categories, plus negative prompts). A copy dropped into the app's Documents via the Files app overrides the bundled one.
- Scoring is **raw cosine similarity with absolute thresholds** (`ScanTuning.clipRejectCosine` / `clipAcceptCosine`), deliberately not softmax, so out-of-vocabulary crops honestly return no match. Crops most resembling a negative prompt (wall, floor, blur) are rejected outright.
- Every crop is classified — including live-scan seeded crops, which previously skipped classification entirely. `VNClassifyImageRequest` is gone.
- Text embeddings for the vocabulary are computed once with the MobileCLIP text encoder (prompt-ensembled over 3 templates) and cached in Application Support keyed by a hash of the vocabulary file. The image encoder runs per crop (~4 ms on device).
- OCR/barcodes remain corroborating evidence; confidence boosts unchanged. All shared thresholds and label sets live in `Inventory/Support/ScanTuning.swift`.
- Vision + Core ML work now runs off the main actor (the old pipeline blocked it).

## Models

MobileCLIP-S2 encoders are **not in git** (127 MB text encoder). `scripts/fetch-mobileclip.sh` downloads them from `apple/coreml-mobileclip` on Hugging Face into `Inventory/MLModels/` (gitignored), plus the CLIP tokenizer assets. Run it once before `xcodegen generate`. The tokenizer Swift code in `Inventory/Support/MobileCLIP/` is vendored from Apple's `ml-mobileclip/ios_app` (MIT).

The generic `yolo26n` model is still downloaded/cached by the UltralyticsYOLO package on first YOLO use; it only supplies boxes now, so its 80-class vocabulary no longer caps naming quality. The old local-model lookup (`inventory-yolo` etc.) remains for a future better localizer.

License note: MobileCLIP v1 Core ML weights were published under Apple's permissive weights license; the repo has since moved to a research-only license for new models. Fine for this personal, undistributed app; recheck before any public release. MobileCLIP2 (better accuracy, same architecture) has **no Core ML exports yet** — when Apple publishes them, the S2 variant should be a drop-in weight swap.

## Calibration

`ScanTuning` constants were set from Apple's demo (cosine 0.22 threshold) and adjusted against simulator runs: reject 0.20, accept 0.26, saturation 0.38, mapped to the app's existing 0...1 confidence scale (reliability cut at 0.42). Recalibrate on real phone captures — log per-crop cosines via the self-test below.

## Self-test harness (simulator, no camera needed)

Debug builds accept `--scan-self-test`: copy test photos into the app container at `Documents/SelfTest/`, launch with the flag, and the full static pipeline (localizers → CLIP → OCR → grouping) runs headless, writing per-image top-3 cosines and final proposals to `Documents/SelfTest/results.txt`.

```sh
DEV=<simulator-udid>
xcrun simctl install $DEV .../HomeInventory.app
CONTAINER=$(xcrun simctl get_app_container $DEV app.homeinventory.catalog data)
cp photos/*.jpg "$CONTAINER/Documents/SelfTest/"
xcrun simctl launch $DEV app.homeinventory.catalog --scan-self-test
cat "$CONTAINER/Documents/SelfTest/results.txt"
```

## Key Files

- `Inventory/Support/MobileCLIPClassifier.swift`: MobileCLIP loading, vocabulary embedding table + disk cache, per-crop zero-shot classification.
- `Inventory/Support/ScanTuning.swift`: every shared threshold and label set (previously duplicated across three files).
- `Inventory/Resources/household-vocabulary.json`: the open vocabulary — names, prompts, categories, negatives, templates.
- `Inventory/Support/MobileCLIP/`: vendored CLIP BPE tokenizer (Apple, MIT) + `clip-vocab.json` / `clip-merges.txt`.
- `Inventory/Support/VideoInventoryAnalyzer.swift`: scan pipeline — candidates, subject lift, CLIP + OCR analysis, naming, grouping.
- `Inventory/Support/YOLOInventoryDetector.swift`: YOLO box supplier (labels now weak evidence).
- `Inventory/Views/ScanVideoView.swift`: scan UI, live `YOLOView` camera path, proposal merging.
- `Inventory/Support/ScanSelfTest.swift`: the headless verification harness (DEBUG only).
- `Inventory/Models/InventoryItem.swift`, `Inventory/Stores/InventoryStore.swift`, `Inventory/Views/ReviewDetectionsView.swift`: models, persistence, review.
